WHAT CHANGED SINCE THE BOOT SOAK
The player now carries a real qualification pass, enabled only by the
-gameSmokeTest switch (Assets/_Game/Core/Bootstrap/GameSmokeTest.cs). It is
inert in a normal build: without the switch the hook returns immediately and
creates nothing. With it, the player:

  1. loads every gameplay scene through the SceneReady handshake and fails if
     any transition times out or never signals readiness
  2. collects all evidence, completes the critical-path objectives to a
     fixpoint through the domain commands, routes the broadcast and transmits
     — asserting the ending is produced
  3. saves and reloads through the real storage layer, asserting the loaded
     state kept the completed broadcast
  then prints SMOKE PASS / SMOKE FAIL and exits 0 / 1.

RUN (ci/smoke-player.sh resolves the executable from the bundle, so the
product name can change without breaking it):

  ./ci/smoke-player.sh
  OK: SMOKE PASS — scenes, progression and save round-trip verified.

The first run FAILED — "the archive pull did not settle behind search_office"
— because the harness completed objectives in content order. Fixing it exposed
a real hole: CompleteObjectiveCommand could complete an Explicit objective
without its owning action, so "an action, not a pickup" was only a convention.
ObjectiveService now refuses Explicit objectives on the command path; only the
domain action (RouteBroadcastCommand / CompleteBroadcastCommand) completes
them. The harness also now iterates to a fixpoint, matching how the chain
actually settles.

WHAT THIS STILL DOES NOT COVER
  - No input is driven: mouse/stick look, movement and UI open/close are not
    exercised in the player. Those rest on PlayerLookTests / PlayerMovementTests
    / UiQualificationTests against the real Input System in the editor.
  - The pass walks the critical path; it does not explore alternative player
    choices (that is what the EditMode reachability check is for).
  - Nothing here verifies that the game LOOKS right.
