CORRECTION to the earlier note below: ai.assistant is NOT player-free. It
copies Unity.AI.MCP.Runtime.dll (9.7 KB) and Unity.AI.Tracing.dll (28 KB) into
the player's Managed/ directory. It is kept for the Unity MCP development
workflow, which is a deliberate ~38 KB trade, not a free dependency. A minimal
release player needs a manifest without it. asset-manager-for-unity does not
ship.

So a stealth game that uses none of these ships all of them. The likely origin
is the template's feature packs (com.unity.feature.characters-animation,
.gameplay-storytelling, .worldbuilding, .development), which are aggregate
packages that pull the rest in.

WHY NOTHING WAS REMOVED
  - The review's own guidance is "do not blindly remove packages", and the
    feature packs are aggregates whose removal can break template content that
    is still referenced (materials, shaders, sample assets).
  - Removal cannot be validated from here: it needs a full cycle —
    BuildAll, EditMode + PlayMode, deterministic generation, and a player
    build + smoke — to prove nothing regressed.
  - Two packages ARE load-bearing for the qualification work and must stay:
    com.unity.test-framework (all 78 EditMode / 29 PlayMode tests) and
    com.unity.ui.test-framework / Input System's test framework (the input
    fixtures in PlayerLookTests and friends).

RECOMMENDED ORDER FOR A CONTROLLED PASS
  1. Drop the unused *feature packs* first (characters-animation,
     gameplay-storytelling, worldbuilding) — they are the source of most of
     the transitive bloat — then re-run the full cycle above.
  2. Then the standalone service/tooling packages: com.unity.services.tooling,
     com.unity.services.cloud-build, com.unity.asset-manager-for-unity,
     com.unity.ai.assistant, com.unity.pipeline, com.unity.physics,
     com.unity.behavior, com.unity.timeline.
  3. Re-check the shipped assembly list after each step: the measure of
     success is a smaller ScriptingAssemblies.json, not a smaller manifest.
